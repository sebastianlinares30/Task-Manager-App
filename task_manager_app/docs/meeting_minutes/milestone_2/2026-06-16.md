# Instructor Feedback

The instructor provided the following recommendations:

## Documentation

- Add docstrings to all classes and methods.
- Add type hints to method parameters and return values.
- Improve inline documentation where appropriate.
- Maintain consistent naming conventions.

## Team Contributions

- Every team member must contribute through individual GitHub commits.
- Contributions should be visible through commit history.
- Team members should push their own work instead of sending files directly to others.
- Individual contributions should be clearly reflected in repository activity.

## Project Documentation

- Current documentation is acceptable but requires more depth and detail.
- UML diagrams, SRS documents, and project planning documents should demonstrate meaningful contributions from all team members.
- Documentation should include additional perspectives and implementation details where appropriate.

## Backlog Management

- Current backlog items are too high-level.
- User stories should be broken into smaller technical tasks.
- Tasks should be measurable and achievable within a few days.
- Development tasks should clearly describe implementation work from a developer perspective.

## Technology Decisions

- The team should finalize the technology stack as soon as possible.
- A final decision should be made regarding the application's user interface approach.
- The instructor emphasized that major technology decisions should not continue to be postponed because they affect future development.

## Data Storage

The team explained that JSON is currently being considered as the primary storage solution. The instructor discussed JSON, XML, and SQLite as possible options and explained that JSON would be acceptable for this project. He also suggested that the team could begin with JSON and later transition to SQLite if needed.
